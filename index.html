02

A control can be correct and still sit in the wrong place.

A

Position A

Filter after ranking.

The answer disappears as soon as documents the caller cannot read fill the top of the list.

B

Position B

Filter before ranking.

The same query returns the same answer, for every caller, at the same cost.

C

The difference

Nothing about the rule changed.

Only where it sits. Most of the work is choosing the position.

Note

None of this is exotic. It is the same discipline as putting authorization on the server instead of the client, moved to a place where most people are still learning it.

03

Two measurements, because a claim without a number is a wish.

permission-rag

Python · retrieval · evals

Recall after ranking and then filtering, once 20 restricted near-duplicates compete per topic. Filtering before ranking holds at 100% across the same sweep.

Repository Chart

37%

Sixty topics, 40 shuffles per point, 2,400 trials. The measured values reproduce the closed form, which is the only reason to trust them. My first two versions of this benchmark showed a flat 100% and were both wrong: tie-breaking, token length and digits in the topic names were deciding the result instead of relevance.

web-posture

Python · security · CI

Score on the first run against a domain I administer: no DMARC record, no SPF, no content security policy.

Repository Checks

49/100

Passive checks only: mail policy, TLS, headers, cookie flags and files that should never be served. It refuses to scan without an explicit authorization flag and a recorded reason, because the difference between a posture check and an incident report is a signature.
